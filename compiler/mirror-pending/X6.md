# X6: keywords as functions (L14), what the stage-2 checker must reproduce (mirror pending)

Mirror duty is suspended (owner, 2026-10-02): nothing under `compiler/` is edited. X6 changes the
checker and its elaboration, no expander and no prelude. The fibber port in `compiler/types/`
(`infer/` and the elaboration X5 mirrors) must do the same, or a program with `(:k x)` or
`(map :k xs)` differs in `compare.sh` (the `expr` and `inst` rows).

## Checker

| Rust | Behaviour | Shown by |
|---|---|---|
| `types/infer/call.rs`, `Cx::keyword_call` (from `Cx::call`) | A call whose head is a keyword literal with one or two `Arg::Expr` arguments is not typed as a call of a `keyword`: the operand `x` (and a default `d`) are inferred, the result is a fresh `R`, and `DKind::Keyword(head.id, S, k, R, dflt)` is deferred. Other arities fall through to the old `cannot unify keyword with (fn ..)`. | cases 1000, 1601, 1602, 1603 |
| `types/infer/call.rs`, `Cx::apply` (`Cx::expects_fn`, `Cx::keyword_fn`) | A keyword literal argument whose parameter type is, shallowly resolved, a `Ty::Fn` is typed `(fn κ (S) R)` (fresh `S`, `R`, `κ`; `κ` is recorded in `u.fn_lits` for the node, as a `fn` literal's) and defers the same `DKind::Keyword`. A keyword for a parameter that is a variable is still a value. | 1601 (`map`, `sort-by`, `group-by`, `filter`), 1000 |
| `types/infer/solve.rs`, `Cx::solve_keyword`, `solve_keyword_map` | Stuck while `S` is a variable. A struct with the field `k`: `R` is the field's type at the struct's arguments (as `solve_field`), a default is an error (`(:k x d): T is a struct, a default needs a map`), `kw_sites[site] = Field`. A struct without it: `NoField`, `T has no field :k`. The prelude's `Map`: `map-get`'s scheme is instantiated at `site` (an `inst` row at the keyword's node, no resolution), its key unified with `keyword` (else `cannot apply :k: the map's keys are not keywords`), `R` with its `(Option v)`, or with `v` and the default's type with `v` when there is a default; `kw_sites[site] = Map`. Anything else: `cannot apply :k to T: it is neither a struct nor a (Map keyword v)`. Left over at the close of the unit: `FieldUnresolved`, `cannot infer the type of the argument of :k; annotate it` (`general.rs`, `check_unresolved`). | 1610, 1611, 1612 |
| `types/infer/cx.rs`, `Tables::kw_sites`, `KwSite` | The new table, read by the elaboration only. | |

## Elaboration (`types/elab/kw.rs`, called from `types/elab.rs`, `Elab::expr`)

Before descending, a `Call` whose head is a keyword in `kw_sites` is rewritten whole
(`Elab::keyword_call`): its arguments are elaborated, then `Field` for a struct, else
`(map-get x :k)` (a `Global(Fun map-get)` head typed `(fn :send (S keyword) (Option v))`, the
`inst` row moved from the keyword's node to the new head's, a fresh `keyword` literal), and with a
default `(match <that> ((some v) v) (_ d))`. A keyword literal in `kw_sites` that is not a call head
becomes `Fn` of one parameter (`keyword-arg`, kind `Param`, typed `S`) whose body is the same read
(`Elab::keyword_fn`); the node keeps its id, type and `fn_colours` entry. Later passes (ownership,
interpreter, `fibc`) see only `Field`, `Call`, `Match` and `Fn`.

The stage-2 table: `types.infer` needs the deferred keyword constraint and its solution, and the
elaboration the same rewrite, with `map-get` found as `g.value(prelude, "map-get")`.
