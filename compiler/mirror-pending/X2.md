# X2 (E3 bracket binding forms, E4 flat `cond`): what the fibber expander must catch up with

Mirror duty is suspended, so `compiler/expand/*.fib` carries none of this except the migration of its
own `cond` uses (the programs compile and run under the Rust front end, which now reads only the flat
`cond`). Until the re-sync, the fibber expander reads the paired `cond` and so fails on every program
that loads `lib/fib/core/protocols.fib` or `lib/fib/print/show.fib` (each has one flat `cond` now):
`compiler/tests/types/compare.sh` on 30 `cases/ownership` files reports 30 different, each
`malformed cond: a clause is (test body+)` at protocols.fib:40. With the patch below applied (not
committed; `X2-cond-expand.patch` in this directory, made against the migrated
`compiler/expand/prelude.fib`) `fibc build compiler/types.fib` builds and the same 30 files give
28 same, 2 different (`cases/ownership/105` and `116`: user macros, `MacroNeedsEvaluator` in the
fibber tool; not cond).

## Rust changes and what each fibber function must do

| Rust (crates/fibref/src/expand) | What it does now | Case or test that shows it | compiler/ function to change |
|---|---|---|---|
| `brackets.rs`: `has_brackets`, `rewrite`, `pairs`, called from `expr.rs::expand_head` (after the macro tests, before `params::fn_has_patterns`; no step counted, nothing admitted) | `(let [a 1 b 2] ..)`, `(loop [..] ..)` become the paired `(let ((a 1) (b 2)) ..)`; a name ending in `:` takes the type and the value (three items); an incomplete binding is `malformed let/loop: a binding is a pattern and an expression, or name: a type and an expression` at the first form of the binding; `(fn [x y] ..)` and `(fn name [x y] ..)` become the list parameter list (patterns still go on to `params::desugar`) | unit `expand::tests::brackets::*`; cases 1205, 1206, 1209, 1210, 1211 | `compiler/expand/expr.fib` (the expand-head loop: add the bracket rewrite before the pattern-parameter desugar); a new helper beside `params.fib` for `pairs` |
| `prelude/logic.rs::cond` | flat `(cond t1 e1 t2 e2 ..)`; any keyword test is always true and must be the last (`malformed cond: a keyword test must be the last`, at the test); the symbol `else` is a variable; an odd number of forms is `malformed cond: a test with no expression` at the last form; the no-default trap is unchanged | unit `expand::tests::prelude::cond_*`; cases 1200 to 1204 | `compiler/expand/prelude.fib`: `cond-macro`, `cond-fold`; `is-else` and `bad-clause` go. The verified replacement is `X2-cond-expand.patch` |
| `prelude/logic.rs::option_binding` (`if-let`, `when-let`) | the binding may be `[p e]` as well as `(p e)` (`brackets::seq_items`); the message says `[pattern expression]` | unit `brackets::if_let_and_when_let_take_a_bracket_pair`; case 1207 | `compiler/expand/prelude.fib`: `option-binding` (accept a vector item list) |
| `prelude/loops.rs::dotimes`, `literal_fn` (`for-each`) | `(dotimes [i n] ..)`; `(for-each (range a b) (fn [i] ..))` is read as the literal one-parameter fn | unit `brackets::dotimes_takes_a_bracket_pair`, `reduce_and_for_each_read_a_bracket_fn`; case 1207 | `compiler/expand/prelude.fib` (the dotimes macro and the for-each literal-fn test) |
| `prelude/reduce.rs`: `Shape::Flat(n)` (the tails of a flat `cond` are every second item after the test at `n`), `literal_fn` accepts `[acc x]` | a `cond` in a reduce tail reads `reduced`; a bracket `fn` is the literal fn the macro rewrites | unit `brackets::a_cond_in_a_reduce_tail_reads_the_flat_form`, `prelude_reduce::every_tail_is_found_through_the_forms_a_body_nests`; case 1208 | `compiler/expand/prelude/reduce.fib`: the shape function (`TailClauses` for `cond` becomes a flat walk), the literal-fn test |

`compiler/types/**` needs no change: the checker lowers expanded forms, which are all parenthesised.
`fuse/scan.rs` reads expanded forms too, so `compiler/expand/fusescan.fib` needs none.

## Test inputs (compiler/tests/expand)

The migration script rewrote the `cond` of 31 inputs mechanically (default `:else (trap ..)` added where
there was none). The paired-syntax edge inputs `porter4c-016` to `-033`, `-218`, `r6b-033` now test
other things under the flat form (`(cond ((< 1 2)))`, `(cond ())`, `(cond 1)` are the odd-count error;
`(cond ((= 1 1) 1) 7)` is a valid two-form `cond` whose test is a call); re-derive them when the
expander is re-synced.

## fibmut

`crates/fibmut/src/ops`: `cond_form` (walk), `clause` and `tails` (shapes) read the flat `cond`; unit
test `clause_deletes_one_clause_of_a_match_or_a_cond`. The bracket `let` is read as a vector literal
(its literals are offered as before); a finer walk of bracket bindings is not done.
