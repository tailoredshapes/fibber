# X4: what the stage-2 expander and checker must reproduce (mirror pending)

Mirror duty is suspended (owner, 2026-10-02): `compiler/expand/*.fib` is not edited and
`bootstrap_expand` is not run. Each Rust change of X4 is listed with the case or test that shows it.

## Expander (reproduce in `compiler/expand/`)

| Rust | What it does now | Shown by |
|---|---|---|
| `crates/fibref/src/expand/params.rs`, `desugar` and `fn_has_patterns` | A `fn` literal whose parameter list holds a pattern item is rewritten before its operands are walked: a bare vector `[k v]` becomes a fresh parameter `#param.N` (`ctx.gensym("param")`), `(PAT :as p)` becomes `p`, `(PAT :as p: T)` becomes `p: T`; one `(let ((PAT p) ..) body..)` wraps the body forms, after the `-> T` and `:where` annotations. A type after `x:` is never read as a pattern. | unit tests `expand::tests::params::*`; cases 1400, 1401 |
| `expand/params.rs`, `desugar(.., defun = true)`, called from `top.rs` `definition_of` for `"defun"` | The same rewrite for a `defun`, which wants every pattern parameter typed: a bare vector or `(PAT :as p)` is `Malformed { head: "defun", reason: "a pattern parameter is (pattern :as name: type)" }`. | `a_defun_pattern_parameter_without_a_type_is_refused`; cases 1402, 1403 |
| `expand/expr.rs`, `expand_head` | After the macro checks, a `fn` with a pattern parameter is one more rewriting step (`ctx.step`), then the loop goes round again. | `a_bare_vector_in_a_fn_is_a_fresh_parameter_and_a_let` |

## Checker (stage 4; not an expander change)

| Rust | What it does now | Shown by |
|---|---|---|
| `types/lower/pattern.rs`, `let_pattern` and `prefix` | A `let` or `loop` binding pattern may be refutable; every exact vector pattern in it is open at the end (`[a b]` is `[a b & _]`). Returns whether it is refutable. | cases 1404, ownership 144 |
| `types/lower/bindings.rs`, `let_chain`, `trap_clause` | Irrefutable bindings stay one `Let`; a refutable one is `Match(init, [pat -> rest, fallback _ -> (fib.prelude/trap "let: pattern does not match")])`. | cases 1405, 1406 |
| `types/ast.rs` `Clause::fallback`, `infer/exhaust/mod.rs` `check_match` | The trap clause is not reported as a redundant clause. | case 1406 (fails with "redundant match clause" without it), 1407 (a written `_` is still redundant), unit test `a_refutable_let_pattern_is_a_match_whose_last_clause_traps` |
| `types/lower/expr.rs`, `loop_form` and `loop_body` | A loop binding whose pattern is not a symbol is a hidden loop variable `#loop.N`; the pattern is bound by `let_chain` at the top of the body, so `recur` passes the whole value. | case 1408 |
| `types/decls.rs` `Globals::is_tuple`; `infer/pattern.rs` `check_tuple_pattern`, `settle_vec_pattern`, `DKind::VecPat` (`infer/cx.rs`, `infer/solve.rs`, `infer/general.rs` `default_vec_patterns`) | A vector pattern against a `Pair` or `Triple` names the fields in order, all of them; against a scrutinee whose type is still a variable it is deferred (each element pattern gets its own type) and settled when the type is known, else a `Vec`'s at the close of the unit. | cases 1400 (Map entries), 1409, 1410; unit tests in `types/tests/patterns.rs` |
| `infer/exhaust/matrix.rs` `tuple_column` | In a `Pair` or `Triple` column a vector pattern is the struct's one constructor over its fields. | case 1409 |
| `eval/pattern.rs` `vec_matches`; `fibc/src/lower/pattern.rs` `vec_pattern` | A vector pattern against a struct value (interpreter) or a tuple type (compiler) matches the fields as a constructor pattern. | cases 1409 under `fibref cases` and `fibc cases` |
