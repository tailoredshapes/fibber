# Buffered I/O in Fibber

Status: proposed API for owner review. The owner approved the buffered scope
and requested a Clojure-inspired API with fewer Java concepts. No implementation
or test results are claimed here.

## Scope and approach

Implement synchronous buffered I/O in `fib.io`, normally qualified as `io`.
Use `fib.unix` for descriptor operations and `(Array i8)` for binary data.
Paths are strings; handles are plain Fibber values. There is no File object,
class hierarchy, implicit charset, or dependency on sockets or readiness.

A small set of whole-file functions alone would leave every streaming caller
to build buffering. A general stream framework would add adapters and protocol
design before there are consumers. Start with concrete Reader and Writer handles
and private transport functions that can also be exercised with scripted tests.

## Proposed public operations

Every fallible operation returns `(Result value IoError)`. Signatures below
show the successful value. `unit` means success with no payload.

| Call | Successful value | Meaning |
|---|---|---|
| `(io/reader path)` | Reader | Open a buffered reader owning its descriptor |
| `(io/writer path)` | Writer | Create or truncate, mode 0666 subject to umask |
| `(io/appending-writer path)` | Writer | Create or append using O_APPEND |
| `(io/reader-fd fd)` | Reader | Borrow a descriptor; caller keeps ownership |
| `(io/writer-fd fd)` | Writer | Borrow a descriptor; caller keeps ownership |
| `(io/read-bytes r n)` | `(Array i8)` | Up to n bytes; empty at EOF or for n = 0 |
| `(io/read-exactly r n)` | `(Array i8)` | Exactly n bytes or an unexpected-EOF error |
| `(io/write-bytes w bytes)` | unit | Accept all bytes into the buffered writer |
| `(io/read-line r)` | `(Option str)` | One UTF-8 line; nil only at EOF before any data |
| `(io/write w text)` | unit | Write the UTF-8 bytes of text |
| `(io/write-line w text)` | unit | Write text followed by LF |
| `(io/flush w)` | unit | Drain pending bytes to the descriptor |
| `(io/close h)` | unit | Close a reader or flush and close a writer |
| `(io/slurp path)` | str | Read the whole file as strict UTF-8 |
| `(io/spit path text)` | unit | Write the whole file, flush, and close |
| `(io/slurp-bytes path)` | `(Array i8)` | Read the whole file without decoding |
| `(io/spit-bytes path bytes)` | unit | Write all bytes, flush, and close |
| `(io/copy r w)` | i64 | Transfer bytes to EOF; return byte count |

Use narrow protocols only where needed to dispatch shared operations such as
close. Do not expose a general adapter framework in this version. Default
buffer size is 8192 bytes; internal constructors accept small capacities for
boundary tests. Public buffer tuning and keyword option maps are deferred.

The existing implicit `slurp`, `try-slurp`, and `spit` retain their signatures
and behavior. Qualified io functions are separate exports. This is a proposed
extension to the standard-library spec, not a silent change to existing rows.
The proposed reader-taking `io/read-line` is distinct from the spec's future
zero-argument operation using dynamic input. `read` remains reserved for forms.

## Bytes, buffering, and text

Handle state lives in Cells and is not Send. Aliases share cursor, buffer, and
closed state. Buffered handles must not be interleaved with raw I/O on the same
descriptor. Read-ahead on a borrowed descriptor may consume bytes beyond those
returned to the caller; closing the wrapper discards that unread buffer.

Store arrays and offsets privately; no new language byte-buffer primitive is
required by the design. Accumulate whole-file reads and long lines in chunks
and flatten once, avoiding repeated copying of the entire accumulated input.

Reads and writes retry EINTR. Short transfers are normal. read-bytes can return
short; read-exactly loops. A nonempty low-level write returning zero is a
WriteZero error. Other errno values propagate without spinning or waiting.
Negative counts are InvalidArgument; zero-length operations do no system I/O.
Closed handles reject operations, including zero-length operations.

write-bytes success means the writer accepted the input, not that it reached
the OS. flush drains pending data; it is not an fsync durability guarantee.
copy does not close either handle or implicitly flush the destination.

read-line recognizes LF, CRLF, and CR, including a CRLF crossing a buffer
boundary. It removes the terminator, preserves empty lines, and returns the
final unterminated line once. A CR lookahead preserves any following non-LF
byte. UTF-8 sequences may cross refill boundaries. Validate a complete line
before constructing a str; invalid bytes produce InvalidUtf8, never a decoding
trap. The offending line is consumed through its terminator. slurp validates
the complete input and preserves all newline bytes.

## Errors and partial progress

IoError carries an operation name, an error kind, bytes progressed by that
operation, any consumed partial input bytes, and an optional cleanup failure.
Kinds are Os(errno), UnexpectedEof, InvalidUtf8, WriteZero, Closed, and
InvalidArgument. Keep numeric errno intact; errno-text is presentation only.

On a failed read-exactly, the error includes all bytes already consumed.
An invalid-text error includes the bytes that failed decoding. On a failed
write-bytes, progress is the prefix accepted from this call, including bytes
still buffered; a caller must not resend that prefix. A failed flush reports
bytes drained during that flush and retains the unwritten suffix in order.
copy reports bytes accepted by the destination and includes any source bytes
read but not accepted, so partial transfer is not hidden.

## Resource lifetime

Opening by path owns the descriptor. reader-fd and writer-fd borrow it; their
close releases wrapper state without closing the descriptor. They support
fib.unix/stdin, stdout, and stderr without introducing global mutable buffers.

close is idempotent after successful closure. An explicit writer close first
flushes; if flush fails, leave the handle open with pending bytes for recovery.
After an attempted OS close, invalidate the handle even on error and do not
retry close on EINTR, to avoid closing a reused descriptor.

Provide call-with-reader, call-with-writer, and call-with-appending-writer.
Each takes a path and a callback returning `(Result a IoError)` and returns the
same result type. They attempt cleanup after both Ok and Err. Their owned
handle is invalidated after the callback even when an alias escapes. If flush
fails during scoped cleanup, still attempt descriptor close and report data
loss as the flush error. A body error remains primary; cleanup errors are
attached. Whole-file helpers use the same cleanup rules.

These helpers cover ordinary Result control flow, not process termination or
traps. with-open and automatic destruction remain deferred to the scope-exit
language work already identified in the standard-library spec. Lazy line-seq
is deferred until its lifetime and error contract can be specified separately.

## Implementation boundaries and validation

Use `lib/fib/io.fib` as a facade and small modules under `lib/fib/io/` for
errors, buffering, readers, writers, text validation, and whole-file helpers.
Respect repository size limits. Add proposed API rows and semantics to
`spec/stdlib.md` only after approval; preserve the existing core contracts.

Use stage 2 as the acceptance harness, per the owner's instruction. First
locate and run its existing S5 cases 3600–3609. New cases must state verdicts
before implementation and use a free case-number block outside S5's reserved
3600–3649 range. Do not extend the frozen Rust tools.

Scripted transports must exercise the same private loops as real descriptors:
short writes followed by EINTR and success; partial progress then an errno;
zero-progress writes; short reads then EOF; flush retry without duplication;
and combined operation and cleanup errors. Real-file and pipe cases cover
binary bytes, empty input, append/truncate, owned and borrowed descriptors,
repeated close, and copy across buffer boundaries.

Text cases cover each UTF-8 width, split sequences, invalid and truncated
sequences, empty lines, CR/LF/CRLF boundaries, and an unterminated final line.
Reference cases compare byte concatenation and transfers against simple
models, with planted faults following spec/method.md. Record actual harness
results and audit availability; do not substitute claims of Rust parity.
